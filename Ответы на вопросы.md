# Ответы на контрольные вопросы

## Лабораторная работа 1

### 1. Три принципа ООП. Пример.

Инкапсуляция объединяет состояние и методы, скрывая детали реализации: массив моделей Car объявлен private. Наследование позволяет строить новый класс на основе существующего: class ElectricCar extends Car. Полиморфизм позволяет работать через общий тип: Transport t = new Motorcycle("Honda", 0); вызов t.getPrices() использует реализацию Motorcycle. Реализация интерфейса даёт полиморфизм без наследования состояния.

### 2. Классы и объекты. Свойства объектов. Пример.

Класс — описание структуры и поведения, объект — конкретный экземпляр класса. Объект имеет состояние, поведение и идентичность. У двух Car с одной маркой могут совпадать данные, но это разные объекты: a == b сравнивает ссылки. Пример создания: Car a = new Car("Toyota", 2).

### 3. Члены класса. Модификаторы объявления класса.

Члены класса — поля, методы и вложенные типы; конструкторы и блоки инициализации входят в объявление класса, но формально не являются его членами. Для класса верхнего уровня допустимы public либо пакетный доступ, а также abstract, final, strictfp; современные версии Java поддерживают sealed/non-sealed при соответствующих условиях. private, protected и static применяются к вложенным классам. abstract запрещает прямое создание экземпляра, final — наследование.

### 4. Пакеты.

Пакет объединяет связанные типы и задаёт область пакетного доступа. Объявление package labs; располагается перед импортами. Полное имя класса — labs.Car. import позволяет использовать короткое имя, но не копирует код и не импортирует подпакеты. Иерархия имён пакетов не создаёт наследования или общего пакетного доступа.

### 5. Пространства имен.

Пространство имён позволяет различать одинаковые короткие имена. Например, java.util.Date и java.sql.Date — разные типы; один можно импортировать, другой указывать полностью. Java различает контексты имён пакетов, типов, переменных, методов и меток; правила области видимости определяют, какое объявление доступно.

### 6. Модуль компиляции.

Модуль компиляции в этом контексте — исходный файл .java с необязательным package, импортами и объявлениями типов верхнего уровня. В обычной файловой сборке публичный класс Car должен находиться в Car.java. javac создаёт .class, в том числе отдельные файлы для вложенных классов. Это понятие не следует смешивать с именованным модулем JPMS, описываемым module-info.java.

### 7. Поля.

Поле хранит состояние объекта или класса. Нестатическое поле своё у каждого экземпляра, static-поле общее для класса. final запрещает повторное присваивание после инициализации, но не делает сам ссылочный объект неизменяемым. Поля получают значения по умолчанию: 0, false, null; локальные переменные перед чтением нужно явно инициализировать.

### 8. Методы. Метод main.

Метод определяет операцию, имеет имя, параметры, возвращаемый тип и тело либо объявление без тела в допустимых случаях. Перегрузка различает методы по списку типов параметров, а не только по возвращаемому типу. Классическая точка входа: public static void main(String[] args). static позволяет вызвать её без объекта, args содержит аргументы командной строки.

### 9. Модификаторы доступа.

public предоставляет доступ отовсюду с учётом доступности содержащего типа и модулей; protected — из пакета и наследникам с ограничениями доступа через ссылку вне пакета; отсутствие модификатора — только внутри пакета; private — внутри соответствующего верхнеуровневого типа и его вложенных типов. Модификаторы ограничивают обращение к реализации, а не заменяют проверку корректности данных.

### 10. Создание объектов. Конструкторы.

new выделяет объект, инициализирует поля и вызывает конструктор. Конструктор называется как класс и не имеет возвращаемого типа. Если конструкторы не объявлены, компилятор предоставляет конструктор без параметров. В Java 17 вызов this(...) или super(...) должен быть первой инструкцией конструктора; если его нет, вставляется super(). Конструкторы не наследуются.

### 11. Блоки инициализации. Статическая инициализация.

Статические инициализаторы и инициализация static-полей выполняются при инициализации класса в порядке объявления, после инициализации суперкласса. При создании экземпляра сначала выполняется конструктор суперкласса, затем инициализаторы полей и блоки экземпляра, затем оставшееся тело конструктора. В Motorcycle блок экземпляра задаёт lastModified и замыкает голову списка.

### 12. Простые типы. Массивы.

Восемь примитивных типов: byte, short, int, long, float, double, char, boolean. char хранит одну кодовую единицу UTF-16, поэтому не каждый символ Unicode помещается в один char. Массив — объект фиксированной длины, индексация начинается с нуля, длина доступна через length. Двумерный массив — массив ссылок на массивы. Arrays.copyOf создаёт новый массив; ссылочные элементы копируются неглубоко.

### 13. Исключения. Родительский класс исключений. Выбрасывание исключений.

Исключение прерывает обычное выполнение и передаёт управление подходящему обработчику. Корень иерархии — Throwable; основные ветви — Error и Exception. throw new NoSuchModelNameException(name) создаёт и выбрасывает объект исключения. Для обычных ошибок приложения используют Exception или RuntimeException, а не Error.

### 14. Объявляемые и необъявляемые исключения. Пример.

Проверяемые исключения — подклассы Exception, не являющиеся подклассами RuntimeException: их нужно обработать либо объявить в throws. Пример — IOException или NoSuchModelNameException. Непроверяемые — RuntimeException и Error с подклассами; обязательного объявления нет. ModelPriceOutOfBoundsException наследует IllegalArgumentException и относится к непроверяемым.

### 15. Синхронные и асинхронные исключения. Пример.

Синхронное исключение возникает как следствие определённой операции: деление целого числа на ноль вызывает ArithmeticException. Асинхронное исключение теоретически может возникать независимо от текущей операции, например при внутренней ошибке виртуальной машины. Исторический Thread.stop мог асинхронно выбросить ThreadDeath и потому небезопасен; в современных JDK он устарел и не является рабочим способом управления. interrupt устанавливает сигнал прерывания, а не произвольно бросает исключение в любой точке.

### 16. Предложение throws.

throws перечисляет типы исключений, которые метод может передать вызывающему коду: void load() throws IOException. Это часть контракта, а не инструкция выбрасывания. Исключение создаёт throw. При переопределении нельзя расширять множество проверяемых исключений относительно контракта исходного метода; можно сузить его или убрать.

### 17. try, catch и finally.

try содержит защищаемый код, catch — обработчик совместимого типа, finally — завершающий код независимо от обычного результата или исключения. Более конкретные catch располагают раньше общих. finally не гарантирован при аварийном завершении JVM. Для ресурсов предпочтителен try-with-resources: он закрывает AutoCloseable и сохраняет ошибки закрытия как suppressed exceptions. return из finally скрывает результат или исключение и нежелателен.

### 18. Интерфейсы. Модификаторы в объявлениях интерфейсов. Пример простого интерфейса.

Интерфейс задаёт контракт типа: public interface Transport { int getSize(); }. Интерфейс верхнего уровня имеет public либо пакетный доступ и не создаётся через new. Он неявно abstract; вложенный интерфейс неявно static. Класс реализует один или несколько интерфейсов через implements; современный интерфейс также может быть sealed.

### 19. Объявление интерфейса. Константы и методы в интерфейсах.

Поля интерфейса неявно public static final и должны иметь инициализатор. Обычные методы без тела неявно public abstract. С Java 8 допускаются default-методы экземпляра с телом и static-методы; с Java 9 — private-методы для внутреннего повторного использования. Статические методы интерфейса вызывают через имя интерфейса. Интерфейс не имеет конструкторов и полей состояния экземпляра.

### 20. Расширение интерфейсов. Наследование и сокрытие констант. Наследование, переопределение и перегрузка методов.

Интерфейс может расширять несколько интерфейсов: interface B extends A, C. Одноимённая константа скрывает унаследованную, а конфликт разрешается квалифицированным именем A.VALUE. Переопределение заменяет реализацию метода с совместимой сигнатурой, перегрузка создаёт другую сигнатуру. При конфликте несвязанных default-методов класс должен явно выбрать реализацию; метод класса обычно имеет приоритет над default интерфейса.

### 21. Пустые интерфейсы. Пример.

Пустой, или маркерный, интерфейс сообщает свойство типа без объявления методов. Пример java.io.Serializable разрешает стандартной сериализации обрабатывать объект. Другой пример — Cloneable, влияющий на Object.clone(), хотя сам метод clone в интерфейсе не объявлен. Аннотации также могут хранить метаданные, но не всегда заменяют маркер там, где нужен типовой контракт.

### 22. Отличия абстрактного класса от интерфейса.

Абстрактный класс может хранить состояние экземпляра, иметь конструкторы и методы с разными уровнями доступа. Класс наследует только один класс, но реализует много интерфейсов. Интерфейс удобен для независимого контракта; абстрактный класс — для общей реализации и инвариантов. Наличие default-методов не даёт интерфейсу собственного состояния экземпляра.

## Лабораторная работа 2

### 1. Потоки данных. Байтовые потоки. Базовые абстрактные классы байтовых потоков.

Поток — последовательный источник или приёмник данных. Байтовые потоки обрабатывают байты; базовые абстрактные классы — InputStream и OutputStream. read() возвращает 0–255 либо −1 при конце, write(int) записывает младшие восемь бит. read(byte[]) может заполнить только часть массива; для заданной длины применяют цикл или DataInputStream.readFully().

### 2. Символьные потоки. Базовые абстрактные классы символьных потоков.

Символьные потоки обрабатывают текст в виде символов Java. Базовые классы — Reader и Writer. Кодировка нужна при преобразовании между байтами и символами, поэтому её следует задавать явно. BufferedReader предоставляет readLine(), Writer — write()/append(); перевод строки не включается в результат readLine().

### 3. Стандартные потоки.

System.in — стандартный InputStream, System.out и System.err — PrintStream для обычного вывода и ошибок. Их может перенаправить оболочка. Закрывать стандартные потоки в вспомогательных методах не следует: ими владеет приложение. Для чтения текста используют new InputStreamReader(System.in, UTF_8).

### 4. InputStreamReader и OutputStreamWriter.

InputStreamReader декодирует байты входного потока в символы, OutputStreamWriter кодирует символы в байты. Это мосты между двумя семействами потоков. Пример: new BufferedReader(new InputStreamReader(in, StandardCharsets.UTF_8)). Если стороны используют разные кодировки, текст будет искажён.

### 5. Примеры байтовых и символьных классов потоков.

FileInputStream/FileOutputStream работают с файлами, ByteArrayInputStream/ByteArrayOutputStream — с памятью, BufferedInputStream/BufferedOutputStream уменьшают число обращений к источнику, DataInputStream/DataOutputStream читают и пишут примитивы. Символьные примеры — FileReader/FileWriter, StringReader/StringWriter, BufferedReader/BufferedWriter, PrintWriter. Обёртки можно комбинировать, сохраняя порядок формата.

### 6. Сериализация объектов. Подготовка классов к сериализации.

Сериализация сохраняет состояние графа объектов в байты, десериализация восстанавливает его. Класс реализует Serializable; все достижимые нестатические нетранзиентные значения также должны быть сериализуемыми. static-поля не являются состоянием объекта, transient исключает поле из стандартного сохранения. В Motorcycle transient lastModified переустанавливается после чтения, поскольку характеризует текущий жизненный цикл объекта.

### 7. Порядок сериализации и десериализации. Настройка механизма сериализации.

ObjectOutputStream.writeObject() записывает объект и достижимый граф, сохраняя общие ссылки и циклы; ObjectInputStream.readObject() восстанавливает его. Конструкторы сериализуемых классов при стандартной десериализации не вызываются; вызывается доступный конструктор без параметров первого несериализуемого суперкласса. private writeObject/readObject с defaultWriteObject/defaultReadObject позволяют изменить формат. Externalizable предоставляет полный контроль. Недоверенные объекты требуют фильтрации типов и ограничений размера.

### 8. Контроль версий объектов.

serialVersionUID задаёт идентификатор совместимости сериализованного класса. При несовпадении ожидается InvalidClassException. Явное private static final long serialVersionUID = 1L делает версию предсказуемой, но не делает произвольные изменения схемы совместимыми. Добавленные поля при совместимом чтении получают значения по умолчанию. Для долговременного обмена обычно выбирают явно версионируемый формат.

## Лабораторная работа 3

### 1. Проблемы однопоточного подхода. Особенности многопоточности.

В одном потоке длительное вычисление или ввод-вывод блокирует последующие действия. Несколько потоков позволяют перекрывать ожидание и использовать ядра процессора, но требуют координации. Конкурентность означает возможность продвижения нескольких задач, параллелизм — их одновременное исполнение. Накладные расходы и общие ресурсы ограничивают ускорение.

### 2. Использование класса Thread.

Можно наследовать Thread и переопределить run(). start() создаёт новый поток исполнения и затем вызывает run(); прямой run() выполняется в вызывающем потоке. Один Thread нельзя запускать повторно. join() ожидает завершения, sleep() приостанавливает текущий поток без освобождения уже захваченных мониторов.

### 3. Использование интерфейса Runnable.

Runnable содержит void run() и отделяет задачу от потока: new Thread(task).start(). Он не возвращает результат и не объявляет проверяемых исключений. Один объект задачи допустимо использовать несколькими потоками, если его состояние безопасно для такого использования. Для результата применяют Callable и Future.

### 4. Управление потоками. Нерекомендуемые действия над потоками. Прерывание потока.

Завершение организуют кооперативно: флагом остановки, interrupt() или отменой Future. interrupt() устанавливает статус, а некоторые блокирующие методы бросают InterruptedException и очищают его. Если исключение не передаётся выше, обычно восстанавливают статус через Thread.currentThread().interrupt(). stop(), suspend(), resume() устарели из-за нарушения инвариантов и взаимных блокировок; пользоваться ими нельзя.

### 5. Группы потоков. Операции в группе потоков.

ThreadGroup исторически группирует потоки и другие группы. Она позволяет перечислять активные потоки приблизительно, задавать максимальный приоритет, выполнять interrupt() для группы и обрабатывать непойманные исключения. Счётчики и снимки не подходят для строгой синхронизации. Для управления задачами предпочтительнее ExecutorService и явное владение их жизненным циклом.

### 6. Приоритеты потоков.

Приоритеты платформенных потоков задаются от MIN_PRIORITY=1 до MAX_PRIORITY=10, обычно NORM_PRIORITY=5. Это подсказка планировщику, а не гарантия очередности или справедливости. ОС может трактовать уровни по-своему. Правильность вывода модель–цена должна обеспечиваться синхронизацией, а не приоритетами.

### 7. Демон-потоки. Пример. Демон-группы потоков.

Демон-поток выполняет вспомогательную работу; JVM может завершиться, когда остаются только демоны. Пример — фоновый наблюдатель с setDaemon(true) до start(). Нельзя поручать ему обязательное сохранение данных без отдельного ожидания. Исторический daemon-флаг ThreadGroup влиял на автоматическое уничтожение пустой группы, но не делал её потоки демонами; эти API устарели и не нужны современному коду.

### 8. Совместное использование ресурсов. Характерные ошибки.

Типичные ошибки — гонки данных, потерянные обновления, отсутствие видимости, deadlock, livelock и голодание. x++ состоит из чтения, изменения и записи и не является атомарным. Доступ к связанным полям защищают общим монитором/Lock; для простых счётчиков подходят атомарные классы, для передачи данных — конкурентные очереди. Единый порядок захвата нескольких блокировок уменьшает риск deadlock.

### 9. volatile.

volatile обеспечивает видимость записей и определённый порядок операций: запись в volatile happens-before последующего чтения этого поля. Он подходит для флага остановки, но не делает составное действие count++ атомарным и не защищает инварианты нескольких полей. В синхронизаторе все обращения к состоянию уже происходят под одним монитором, поэтому дополнительный volatile не обязателен.

### 10. Специальные методы класса Object. Особенности использования методов класса Object.

wait(), notify(), notifyAll() вызывают только владея монитором соответствующего объекта. wait() освобождает этот монитор, при пробуждении снова захватывает его; другие удерживаемые мониторы не освобождает. Условие проверяют циклом while из-за ложных пробуждений и конкуренции. notifyAll() пробуждает всех ожидающих, но не передаёт блокировку немедленно. В лабораторной условием служит очередь вывода имени или цены.

### 11. java.util.concurrent.locks. Lock, ReentrantLock, ReadWriteLock.

Lock — явный интерфейс блокировки с lock(), unlock(), tryLock(), lockInterruptibly(). ReentrantLock допускает повторный захват владельцем; освобождение обязательно в finally. Condition предоставляет аналог ожидания условия. ReadWriteLock разделяет блокировки чтения и записи: несколько читателей могут работать одновременно, писатель требует эксклюзивного доступа.

### 12. Интерфейсы Callable и Future.

Callable<V>.call() возвращает V и может бросать Exception. submit(callable) возвращает Future<V>; get() ждёт результат, get(timeout, unit) ограничивает ожидание. Ошибка задачи оборачивается в ExecutionException; cancel(true) запрашивает прерывание. Future не гарантирует остановку задачи, которая игнорирует прерывание.

### 13. Интерфейсы Executor, ExecutorService, ScheduledExecutorService.

Executor определяет execute(Runnable). ExecutorService добавляет submit, Future, shutdown, shutdownNow, awaitTermination и пакетные операции. ScheduledExecutorService запускает задачи с задержкой либо периодически. scheduleAtFixedRate ориентируется на заданный период, scheduleWithFixedDelay — на задержку после завершения предыдущего запуска.

### 14. Пул потоков. Executors.

Пул повторно использует ограниченное число рабочих потоков. Executors.newFixedThreadPool(2) выполняет не более двух задач одновременно, остальные ждут в очереди. Порядок завершения зависит от длительности задач и планировщика. shutdown прекращает приём задач и даёт принятым завершиться; shutdownNow лишь пытается прервать выполнение. Неограниченная очередь фиксированного пула требует осторожности при большом входном потоке.

## Лабораторная работа 4

### 1. Модель OSI.

Модель OSI включает семь уровней снизу вверх: физический, канальный, сетевой, транспортный, сеансовый, представления, прикладной. Пример сопоставления: Ethernet — канальный, IP — сетевой, TCP/UDP — транспортный, HTTP — прикладной. Реальная архитектура TCP/IP не обязана иметь отдельную реализацию каждого уровня OSI.

### 2. Модель «Клиент-сервер». Понятие порта. Абстракция сокета.

Клиент инициирует запрос, сервер принимает запросы и предоставляет сервис. Порт — 16-битный номер транспортной конечной точки; TCP и UDP имеют отдельные пространства портов. Сокет — программная абстракция конечной точки связи. TCP-соединение различается сочетанием адресов и портов обеих сторон и протоколом; один серверный порт может обслуживать много клиентов.

### 3. Пакет java.net. Класс Socket. Порядок работы с сокетом клиента.

java.net содержит Socket, ServerSocket, DatagramSocket, InetAddress, URI, URL и связанные классы. Клиент создаёт Socket, подключается с тайм-аутом, получает потоки, передаёт запрос согласно протоколу, читает ответ и закрывает сокет. TCP передаёт поток байтов без границ сообщений, поэтому нужен формат длины либо другой способ разбиения. В работе запрос — сериализованный Transport[], ответ — флаг успешности и double либо текст ошибки.

### 4. Класс ServerSocket. Сервер параллельной обработки запросов.

ServerSocket привязывается к адресу и порту; accept() ожидает соединение и возвращает отдельный Socket клиента. Последовательный сервер обрабатывает его до следующего accept(). Параллельный передаёт обработку пулу, продолжая принимать соединения. Пул и очередь желательно ограничивать; ошибки одного клиента не должны останавливать весь сервер.

### 5. Дейтаграммы.

Дейтаграмма — самостоятельное сообщение, обычно передаваемое через UDP. UDP сохраняет границы сообщения, но не гарантирует доставку, порядок или отсутствие повторов. В Java используют DatagramSocket и DatagramPacket. Протокол приложения при необходимости добавляет номера, подтверждения и повторную отправку. Слишком большая дейтаграмма может фрагментироваться.

### 6. Uniform Resource Locator.

URL — адрес ресурса с указанием способа доступа: https://example.org:443/path?q=java#part. Он может включать схему, узел, порт, путь, запрос и фрагмент. URI — более общее понятие идентификатора. java.net.URI удобен для разбора и формирования адреса, URL/URLConnection — для доступа; для HTTP в современном Java также есть java.net.http.HttpClient.

### 1. Класс Graphics. Работа с цветом. Работа со шрифтами.

java.awt.Graphics — контекст рисования AWT/Swing: drawLine, drawRect, fillRect, drawString. setColor(new Color(r,g,b)) задаёт цвет; setFont(new Font("SansSerif", Font.BOLD, 16)) — шрифт. FontMetrics позволяет измерять текст. В Swing рисуют в paintComponent(Graphics), вызывая super.paintComponent(g); для расширенных возможностей приводят к Graphics2D. В JavaFX используются другие API — узлы сцены либо GraphicsContext Canvas.

### 2. Особенности AWT. Менеджеры компоновки.

AWT предоставляет окна, события и компоненты, многие из которых используют нативные peers ОС. Менеджер компоновки вычисляет размеры и положение дочерних компонентов. FlowLayout располагает их потоком, BorderLayout — по областям, GridLayout — одинаковыми ячейками, GridBagLayout — гибкой сеткой, CardLayout переключает панели. Абсолютные координаты хуже адаптируются к шрифтам и размерам окна.

### 3. Модель делегирования обработки событий. Событие. Источник. Слушатель. Пример.

В модели делегирования источник генерирует событие и вызывает зарегистрированных слушателей. Например, JButton — источник, ActionEvent — событие, ActionListener — слушатель: button.addActionListener(e -> calculate()). Источник не должен содержать весь прикладной алгоритм; обработчик вызывает отдельную логику. В JavaFX близкую роль выполняет setOnAction(EventHandler).

### 4. Классы-адаптеры.

Класс-адаптер содержит пустые реализации методов интерфейса слушателя, чтобы переопределять только нужные. Пример: new WindowAdapter() { public void windowClosing(WindowEvent e) { ... } }. Аналогично MouseAdapter и KeyAdapter. Это полезно для интерфейсов с несколькими методами; функциональный интерфейс с одним абстрактным методом удобнее реализовать лямбдой.

### 5. Статические вложенные классы. Вложенные интерфейсы.

Статический вложенный класс объявляется внутри класса со static и не хранит неявной ссылки на внешний экземпляр. Создание: new Outer.Nested(). Он обращается к статическим членам внешнего класса, а к экземплярным — через объект. Вложенные интерфейсы неявно static; интерфейсы, объявленные внутри интерфейса, также public.

### 6. Нестатические вложенные классы. Локальные классы. Анонимные классы.

Нестатический внутренний класс связан с внешним экземпляром и имеет доступ к его состоянию: outer.new Inner(). Локальный класс объявляют внутри блока; анонимный — непосредственно в выражении new Type(){...}. Захватываемые локальные переменные должны быть final либо effectively final. Внутренний Model в Car соответствует требованию задания, но его неявная ссылка на Car также входит в граф сериализации.

### 7. Проблемы AWT. Особенности Swing. Look And Feel.

Нативные компоненты AWT зависят от платформы и дают ограниченную гибкость оформления. Swing расширяет AWT, предлагает богатый набор преимущественно лёгких компонентов и сменяемый Look and Feel. UI Swing изменяют в Event Dispatch Thread, длительные задачи выносят, например, в SwingWorker. LookAndFeel определяет внешний вид и взаимодействие компонентов, но не прикладную логику.

### 8. Создание оконных приложений. Отрисовка компонентов.

В Swing создают JFrame, размещают компоненты через layout, задают закрытие окна, вызывают pack() и setVisible(true) в EDT. repaint() планирует перерисовку, прямой вызов paint() обычно не нужен. В JavaFX аналогично строят дерево узлов и Scene, назначают её Stage и вызывают show(). Вычисления отделяют от UI, чтобы интерфейс не зависал.

### 9. JavaFX. Класс Application и жизненный цикл приложения. Stage. Scene.

JavaFX Application имеет жизненный цикл init(), start(Stage), stop(). start и stop выполняются на JavaFX Application Thread; init — до start и не предназначен для создания Stage/Scene. Stage представляет окно, Scene — графическое содержимое. launch(args) запускает платформу. UI изменяют в FX-потоке, из фонового потока используют Platform.runLater().

### 10. Графические элементы. Класс Node. Взаимодействие с пользователем и обработка событий.

Node — базовый элемент графа сцены: Button, TextField, Label, контейнеры и фигуры. Parent содержит дочерние узлы; GridPane и VBox выполняют компоновку. Пользовательские действия обрабатывают EventHandler, фильтры событий и свойства. Фильтры участвуют в проходе к цели, обработчики — в обратном распространении. В калькуляторе кнопки и клавиатура вызывают общий метод press(), поэтому поведение совпадает.

### 11. Нововведения Java 7.0.

Java 7 добавила try-with-resources, multi-catch, diamond <>, switch по String, двоичные литералы и подчёркивания в числах. Библиотеки получили NIO.2 (Path, Files), Fork/Join и другие улучшения. Пример: try (InputStream in = Files.newInputStream(path)) { ... } автоматически закрывает ресурс.

### 12. Нововведения Java 8.0.

Java 8 добавила лямбды, ссылки на методы, default/static-методы интерфейсов, Stream API, Optional, java.time и CompletableFuture. Лямбда реализует функциональный интерфейс: button.setOnAction(e -> press("="));. Stream позволяет map/filter/reduce, но не является потоком ввода-вывода. В приложении обработчики кнопок реализованы лямбдами, что выполняет условие о нововведении Java 7/8; проект в целом собирается на Java 17+.

## Лабораторная работа 6

### 1. Распределённая система. Причины создания, принципы построения, последствия распределённости, требования к распределённым системам.

Распределённая система состоит из взаимодействующих узлов, связанных сетью и совместно предоставляющих функции. Причины построения — распределение ресурсов и нагрузки, географическая доступность, независимое развитие компонентов, повышение устойчивости. Принципы — явные интерфейсы, согласованные протоколы, управление отказами и безопасностью. Последствия распределённости: задержки, частичные отказы, отсутствие единого надёжного времени и трудность согласования данных. Требования включают доступность, масштабируемость, согласованность и наблюдаемость; их баланс зависит от задачи.

### 2. Распределённая система. Сложности при реализации, модели распределённых систем, архитектура и основные принципы, преодоление сложности.

Главные сложности — сетевые тайм-ауты, дублирование запросов, конкуренция, разные версии компонентов и невозможность сразу отличить медленный узел от отказавшего. Архитектуры: клиент–сервер, многоуровневая, одноранговая, микросервисная, событийная. Модели исполнения бывают синхронными и асинхронными; модели отказов задают, чему можно доверять. Сложность уменьшают идемпотентными операциями, ограниченными повторами с задержкой, транзакциями, очередями, репликацией и трассировкой. При сетевом разделении нельзя одновременно гарантировать строгую согласованность и доступность всех запросов в смысле CAP.

### 3. JDBC. Типы драйверов. Основные цели интерфейса JDBC. Примеры использования JDBC. Основы программирования JDBC. Предварительно подготовленные команды. Метаданные.

JDBC — стандартный Java API доступа к реляционным БД. Тип 1 использует мост к другому API, тип 2 — нативную библиотеку, тип 3 — промежуточный сетевой сервер, тип 4 — Java-драйвер протокола конкретной БД; PostgreSQL JDBC относится к типу 4. Последовательность: получить Connection, подготовить Statement/PreparedStatement, выполнить запрос, прочитать ResultSet, зафиксировать либо откатить транзакцию, закрыть ресурсы.
PreparedStatement отделяет параметры от SQL: SELECT * FROM artist WHERE id = ?; далее setLong(1,id). Это защищает значения от SQL-инъекций и позволяет повторное использование команды; имена таблиц параметрами не подставляют. executeQuery возвращает ResultSet, executeUpdate — число изменённых строк. DatabaseMetaData описывает БД и её объекты, ResultSetMetaData — столбцы результата. В работе setAutoCommit(false), commit и rollback объединяют демонстрацию CRUD в транзакцию.

## Лабораторная работа 8

### 1. ORM. Достоинства и недостатки. Hibernate. Файл hibernate.cfg.xml. Пример.

ORM сопоставляет объекты и связи с таблицами, строками и внешними ключами. Преимущества — меньше повторяющегося SQL, управление состоянием сущностей и единая модель работы. ### 2. Servlet, Servlet container, Distributed servlet container, Servlet context, Servlet mapping. Жизненный цикл сервлетов. Особенности сервлетов. Объекты запроса и отклика. HTTP Servlet. Пример сервлета. Поддержка сессий. Общий дескриптор развёртывания web.xml. Фильтрация.

Servlet обрабатывает запросы в контейнере; Servlet container управляет созданием, маршрутизацией, потоками, сессиями и жизненным циклом. Distributed container допускает размещение приложения на нескольких узлах, поэтому состояние нельзя бездумно хранить в памяти одного процесса. Жизненный цикл: создание, init(), многократные service(), destroy(). HttpServlet направляет HTTP-методы в doGet/doPost и другие обработчики. HttpServletRequest даёт параметры, заголовки и сессию; HttpServletResponse — статус, заголовки и тело. Один экземпляр обычно обслуживает несколько потоков, поэтому данные запроса не хранят в его полях. HttpSession поддерживает пользовательское состояние, обычно через cookie JSESSIONID. web.xml описывает развёртывание; Filter выполняет обработку до/после цепочки, например настройку UTF-8.

### 3. JSP. Принцип работы, обработка ошибок, виды JSP, элементы JSP-страницы. Пример.

JSP — серверный шаблон, который контейнер переводит в servlet, компилирует и исполняет; браузер получает готовый HTML. Жизненный цикл включает jspInit(), _jspService(), jspDestroy(). Есть классический синтаксис .jsp и XML-синтаксис .jspx, а не отдельные технологии выполнения. Элементы: текст шаблона, директивы <%@...%>, декларации <%! ... %>, scriptlet <% ... %>, выражения <%= ... %>, EL и теги. Для ошибок используют errorPage/isErrorPage либо конфигурацию error-page. В современном оформлении вычисления выполняет servlet, а JSP выводит атрибуты запроса через EL/JSTL.

### 4. Директива include. Стандартные объекты. Тэги <jsp:…>. Тэги <jsp:include>. Тэги <jsp:forward>. Взаимодействие с HTML-формами. Примеры.

<%@ include file="fragment.jsp" %> объединяет исходный текст при трансляции. <jsp:include page="..."/> включает результат обработки ресурса во время запроса; <jsp:forward page="..."/> передаёт запрос другому ресурсу, пока ответ не зафиксирован. К стандартным объектам относятся request, response, session, application, out, config, pageContext, page; exception доступен странице ошибок.
Стандартные действия jsp:useBean, jsp:setProperty и jsp:getProperty работают с JavaBean; jsp:param передаёт параметры включению или перенаправлению. HTML-форма отправляет поля по name; servlet читает getParameter(), проверяет значения, сохраняет данные и обычно выполняет redirect, чтобы повторное обновление страницы не повторяло POST.

### 5. Недостатки раннего JSP. Основные идеи смены парадигмы. Expression Language. Виды выражений EL. Пример. Литералы, операторы, объекты доступа к другим объектам. Custom tags. Библиотеки тегов. JSP Standard Tag Library. Библиотеки JSTL.

Ранние JSP со scriptlet смешивали SQL, бизнес-логику и HTML, что ухудшало тестирование и сопровождение. MVC разделяет модель данных, servlet-контроллер и JSP-представление. EL ${album.title} читает свойство getTitle(); ${...} вычисляется немедленно, #{...} служит отложенному вычислению в поддерживающих его контекстах. Есть числовые, строковые, логические и null-литералы, арифметика, сравнение, &&/and, empty и тернарный оператор.
EL обращается к объектам, спискам и картам через . и []; param, header, cookie, requestScope, sessionScope — неявные объекты. Сам по себе EL не гарантирует HTML-экранирование, поэтому текст выводят через c:out. Custom tags инкапсулируют повторяемый шаблон. JSTL включает core, formatting/i18n, functions, XML и SQL; в этой работе используются core c:forEach/c:out/c:remove, а работа с БД остаётся в Java.

### 6. AJAX.

AJAX — асинхронный обмен данными с сервером без полной перезагрузки страницы; XML необязателен, часто передают JSON. В работе событие input после задержки 200 мс вызывает fetch("suggest?..."), servlet выполняет параметризованный HQL и возвращает до десяти строк. JavaScript заполняет datalist элементами option. AbortController отменяет устаревший запрос, ошибки не ломают основную форму. Сервер всё равно обязан проверять входные данные; клиентское автозаполнение не является валидацией или защитой.
